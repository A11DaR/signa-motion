# SIGNA — говори руками

Вводный интерактивный урок американского жестового языка (ASL) для **ADMIT HACKATHON / MOTION**. Обычная веб-камера становится контроллером: пользователь повторяет жест, видит распознанные суставы, получает конкретное исправление и собирает короткую фразу.

**Это прототип с тремя учебными жестами, не универсальный переводчик. ASL и РЖЯ — разные языки.** Для дальнейшего расширения словаря нужна проверка носителем или преподавателем ASL.

## Быстрый запуск

Нужен Node.js 20 или новее. Установка npm-пакетов, ключи API, сервер распознавания и платные API не требуются. MediaPipe, WASM и модель уже включены в `dist`. Нужен современный браузер с WebAssembly SIMD; устаревшие браузеры без SIMD получат подсказку об обновлении.

```bash
npm start
```

Откройте **http://localhost:3000** в браузере и разрешите доступ к камере. Не открывайте `index.html` двойным щелчком: для камеры и загрузки модели нужен HTTP на localhost либо HTTPS.

Другой вариант, если есть Python 3:

```bash
python3 -m http.server 3000 --directory dist --bind 127.0.0.1
```

Для использования на телефоне загрузите содержимое `dist` на HTTPS-хостинг. Адрес вида `http://192.168...` не даёт защищённый контекст для камеры. Сборка не нужна. Все пути относительные: приложение может работать и в подпапке.

## Законченный сценарий

1. Пользователь включает камеру и даёт системное разрешение. Показывает открытую ладонь на 1,4 секунды: приложение проверяет видимость и сохраняет типичный размер ладони. После настройки урок начинается сам.
2. Проходит три задания: I LOVE YOU → YES → NO. Справа — схема, инструкция и образец ASL University. Камера показывает скелет руки; проблемные пальцы выделены тёплым цветом.
3. Выполняет задание **«Да. Я тебя люблю!»**: сначала YES, затем I LOVE YOU. Проверяется заданная последовательность, а не произвольная речь.
4. Получает итог: 3/3 жеста, учебные баллы, время урока без явных пауз и настройки камеры, среднее соответствие правилам, число подсказок и лучший жест.
5. Может начать заново движением руки. Лучший результат хранится только в текущем браузере.

Учебные жесты можно выполнять любой рукой. В кадре должна быть одна рука; две используются только для отдельных команд интерфейса.

## Жесты и правила

| Учебный жест | Проверка | Результат |
| --- | --- | --- |
| I LOVE YOU | Большой, указательный и мизинец раскрыты; средний и безымянный согнуты; ладонь фронтально к камере; удержание 0,7 с | Изученный знак и соответствующая часть фразы |
| YES | Кулак; изменение наклона кисти относительно запястья; возврат в исходное положение и удержание 0,5 с | Подтверждение «Да» и первая часть фразы |
| NO | Безымянный и мизинец согнуты; раскрытые указательный и средний рядом; затем оба кончика смыкаются с большим на 0,5 с | Отрицание «Нет» и завершение изучения словаря |

Для NO выбран вариант с одним смыканием. Допустимые варианты и контекст см. в словаре: приложение не оценивает все варианты ASL.

### Три разных движения для трёх действий интерфейса

Эти команды **не преподаются как ASL**:

| Движение | Действие |
| --- | --- |
| Одна открытая ладонь, 0,4 с | Включает режим курсора. Начальная позиция руки становится центром управления; небольшие перемещения достигают краёв экрана |
| Щипок большого и указательного пальцев | Нажимает кнопку или ссылку под курсором; удержание курсора 1,2 с — альтернативное нажатие |
| Курсор у верхнего / нижнего края | Прокручивает страницу либо открытый диалог |
| Один кулак, 0,5 с | Выключает курсор, закрывает образец и возвращает к упражнению |
| Две открытые ладони, 1,2 с | Пауза / продолжение урока |
| Два кулака, 1,2 с | Открывает / закрывает образец текущего жеста |

Системное разрешение камеры подтверждается обычным способом — браузер не позволяет приложению самостоятельно разрешить доступ. Дальнейший сценарий внутри SIGNA доступен без клавиатуры и мыши. Если в режиме курсора показать начальную форму текущего учебного жеста на 0,4 с, приложение само вернётся к уроку. Этот переход не засчитывает задание: удержание или движение проверяются заново. Также можно сжать кулак или выбрать «К уроку». Открытый образец и явная пауза не закрываются автоматически учебным жестом. Случайный одиночный кадр с открытой ладонью не включает курсор. После нажатия отведите курсор от кнопки, чтобы нажать её повторно. Кнопки управления видео находятся под образцом и также доступны рукой. Ссылки на внешний словарь открывают другой сайт, на который управление SIGNA не распространяется.

## Твист: режим «ошибка»

`dist/landmarks.js` и `dist/gesture-rules.js` вычисляют собственные признаки из 21 точки каждой руки: углы суставов, отношение расстояний к ширине ладони, направление кисти, расстояние до большого пальца и историю движения.

Ошибки разделяются:

- **Положение пальцев:** «Выпрями мизинец», «Согни средний палец к ладони», «Отведи большой палец в сторону». Проблемная группа суставов подсвечивается. Для I LOVE YOU интерфейс отдельно показывает состояние каждого пальца, ладони и удержания.
- **Движение:** «Кивни кулаком вниз и обратно», «Теперь верни кисть в исходное положение», «Коснись большого обоими пальцами».
- **Условия наблюдения:** «Кисть выходит из кадра», «Поднеси руку ближе». Это не записывается как ошибка выполнения.

Три состояния: **Incorrect / «Исправь жест»** — больше двух нарушенных условий; **Almost / «Почти»** — осталось 1–2 условия либо форма правильная, но удержание ещё не завершено; **Correct / «Верно»** — устойчивый жест засчитан. Условия наблюдения показаны отдельно и не уменьшают баллы.

`validateGesture(gesture, features)` возвращает `{gesture, confidence, poseCorrect, checks, errors, badFingers}`. `getGestureErrors()` выделяет конкретные исправления, `detectGesture()` определяет базовую форму. Временной `GestureRecognizer.updateFeatures()` добавляет `correct`, `state`, `progress` и одноразовое событие `success`. Только временной распознаватель может завершить задание.

Смена основной подсказки сглаживается за 250 мс; в статистику попадает только ошибка, сохранявшаяся 1,6 с. Для I LOVE YOU требуется 700 мс подтверждённой формы. Пропуски и небольшие ошибки до 320 мс приостанавливают прогресс, но не обнуляют его; неподтверждённые интервалы не добавляют время. Длительная потеря руки или неверная форма, смена задания, пауза и разрыв кадров более 1,2 с сбрасывают накопление. Для YES сглаживается наклон кисти, проверяются кивок и возврат; NO требует раскрытия перед смыканием. Завершающее положение динамических жестов удерживается 500 мс. Неподвижный кулак и закрытый щипок сами по себе не проходят.

Зачёт фиксируется синхронно в `completed`: повторное событие не добавляет баллы. Зелёное подтверждение остаётся на 800 мс, затем независимый цикл интерфейса переводит урок дальше. Новые координаты камеры для этого не нужны. После перехода есть пауза 250 мс перед оценкой нового жеста. В тесте 3 кадра/с также достаточно для зачёта.

Проценты **«Соответствие»** — взвешенная доля соблюдённых геометрических и временных правил, не вероятность нейросети. Шкала **удержания** отдельно показывает продвижение к зачёту. Среднее соответствие в итогах рассчитывается по наблюдаемым кадрам каждого жеста; это не оценка владения ASL. Учебные баллы: `max(50, 100 − 3 × число устойчивых подсказок)` после полного завершения.

## Калибровка и восстановление

Открытая ладонь должна быть видна целиком, обращена к камере и оставаться на месте. Медианный размер ладони задаёт рабочий диапазон расстояния; углы и расстояния внутри жестов нормализованы по текущей ширине ладони. Калибровка не засчитывает учебные задания и не включает курсор. После неё ладонь нужно отпустить, чтобы намеренно включить управление сайтом. Кнопка «Настроить» позволяет повторить настройку; при смене камеры она запускается автоматически.

Отдельные подсказки объясняют отказ в доступе, отсутствие или занятость камеры, слишком маленькую/большую кисть, выход за край, две руки и слишком тёмный кадр без найденной руки. Яркость измеряется локально раз в секунду; это подсказка, а не медицинская или точная оценка освещения. Загрузка отменяется кнопкой. Поздний результат отменённого подключения освобождается, повторный запуск доступен. При скрытии вкладки урок ставится на паузу, незавершённая калибровка начинается заново. Завершение уже принятого жеста не зависит от поступления новых кадров.

## Что исправлено

- Запуск после загрузки модели падал с `Illegal invocation`: нативные `requestAnimationFrame` и `cancelAnimationFrame` были сохранены как методы `FrameTracker` и вызывались с неверным `this`. Обёртки сохраняют глобальный контекст браузера при запуске, каждом следующем кадре и остановке.
- После сбоя запуска камера продолжала показывать заголовок калибровки. Теперь возвращается текущее задание; ошибка загрузки модели отделена от ошибки запуска обработки.
- Ошибочный знак стороны ладони отклонял правильный I LOVE YOU; условие сверено с настоящими результатами MediaPipe для исходных и зеркальных фотографий.
- Слишком жёсткая проверка крайнего сустава отклоняла естественно выпрямленный палец. Теперь учитываются основной угол и относительная длина пальца вместе.
- Краткие потери распознавания уничтожали удержание; добавлены накопление подтверждённого времени и допустимый промежуток потери.
- Визуальное совпадение, зачёт и переход смешивались. Теперь это отдельные состояния с одноразовым зачётом и независимым переходом.
- Режим курсора мог перехватывать учебный жест. Начальная форма задания возвращает проверку в режим урока, без автоматического зачёта.
- Видео и скелет использовали несовпадающие размеры. Теперь оба вписываются по одной геометрии и зеркалятся вместе.
- Подключение камеры и обработка кадров разделены; повторные запросы, отмена, остановка и поздние результаты имеют явный жизненный цикл.

## Технологии и собственная логика

- HTML, CSS, JavaScript ES modules: без сборщика и фреймворка.
- MediaPipe Tasks Vision **0.10.32**, Hand Landmarker `float16/1` — только определение суставов.
- Собственные геометрические правила, временные автоматы для YES и NO, проверка последовательности, подсказки, команды интерфейса и курсор.
- GPU с резервным CPU-режимом; оба используют локальную SIMD-версию WASM. Обработка ограничена примерно 14 кадрами/с; одновременно выполняется не более одного inference. При остановке освобождаются видеодорожки, модель и цикл обработки. Повторяющиеся ошибки останавливают цикл и предлагают переподключиться. В этой версии inference синхронный на основном потоке; на слабом устройстве возможны задержки.
- Видео сохраняет исходное соотношение сторон. Передняя камера и скелет зеркальны вместе, задняя камера не отражается. Кнопки вынесены под изображение, чтобы не закрывать руку. Canvas и видео используют одинаковую область вписывания.
- Canvas: скелет поверх видео и анимированная учебная схема. Схема условная, для контекста есть образцы автора учебного материала.
- Web Audio: короткий звук успеха, включается пользователем.
- `localStorage`: лучший результат на этом устройстве. Запрет хранилища не мешает пройти урок.
- Русский интерфейс, адаптивная компоновка, смена передней/задней камеры, диалоги и обычные кнопки как дополнительный способ управления.
- Необязательный WebMCP: чтение состояния и перезапуск урока. Он не может засчитать жест или создать результат без камеры.

Видео камеры не записывается и не отправляется в сеть. Модель и WASM загружаются с того же сайта. Образцы YouTube / иллюстрация Lifeprint запрашиваются только при открытии образца.

## Проверка

```bash
npm ci --ignore-scripts  # jsdom нужен только для проверки интерфейса
npm test
npm run check
```

Новая регрессия `startup.test.mjs` нажимает настоящую кнопку запуска в DOM и проводит весь урок через `CameraSession` и `FrameTracker`, затем проверяет остановку, смену камеры, отказ в доступе, ошибку загрузки модели и повторный запуск. До исправления она воспроизводила экран «Не удалось запустить распознавание». Тестовые функции планирования проверяют допустимый получатель вызова, как браузерные Web IDL API; видеоустройство и нейронный inference заменены контролируемыми объектами. Прежние тесты передавали готовые landmarks напрямую и не проверяли этот участок запуска.

Автоматические проверки покрывают полный путь «координаты суставов → распознавание → следующий экран → сохранённый результат», включая калибровку, весь урок и фразу, одноразовый зачёт и отложенный переход без новых кадров камеры. Отдельно проверяются дрожание, 3 кадра/с, потеря руки, ложные совпадения, порядок движения, пауза, баллы, геометрия камеры, щипок, повторные нажатия, прокрутка, модальные окна, управление учебным видео и возврат к распознаванию. В DOM-прогоне перехватываются ошибки виртуальной консоли и необработанные события окна; это не проверка настоящей консоли браузера. YouTube API в тесте заменён контролируемым объектом; доступность внешнего видео этим не подтверждается.

**Регрессия на реальных фотографиях:** MediaPipe 0.10.32 (Python CPU, тот же файл `hand_landmarker.task`, что использует сайт) обработал две фотографии I LOVE YOU. Для каждой проверены исходное и зеркальное изображение с поворотами −15°, 0°, +15°: всего 12 вариантов. До исправления все 12 отклонялись, после исправления проходят проверку формы и автопереход в DOM. Дополнительно 16 наблюдений других форм рук не засчитываются как I LOVE YOU. Калибровка проверена на результате той же модели для отдельной фотографии открытой ладони. Найдены и исправлены неверный знак проверки стороны ладони и слишком жёсткое требование к крайнему суставу выпрямленного пальца.

В `tests/photo-landmarks.json` и `tests/calibration-palm.json` сохранены численные результаты модели, исходные URL, SHA-256 изображений и модели. Фотографии не включены в проект. Для ILY: RGB, размер не более 960×960 с сохранением пропорций, горизонтальное отражение, поворот Pillow BICUBIC. Для калибровки: исходный RGB-кадр. Повторение статичного набора точек проверяет устойчивое правило и переход, а не реальную видеосъёмку.

**Предел проверки:** тесты используют синтетические данные и выход модели на небольшой контрольной выборке фотографий. Это регрессионная проверка, не оценка общей точности на людях. Доступа к физической веб-камере при создании не было. Браузерный предпросмотр Sites требует skill `control-browser`, отсутствующий в этой среде; другие способы браузерного прогона этот workflow не разрешает. Реальная камера, отображение в браузере, производительность на телефоне и WebMCP нуждаются в ручной проверке перед сдачей. Нельзя заявлять процент точности распознавания на основании этих тестов.

Минимальный ручной прогон:

1. Разрешить и отдельно запретить камеру, проверить восстановление и отмену загрузки. Пройти настройку открытой ладони; повторить после смены камеры.
2. Пройти весь урок до результата обеими руками по очереди.
3. Проверить конкретные ошибки: согнутый мизинец для ILY, неподвижный кулак для YES, закрытый щипок для NO.
4. Убрать руку на полсекунды: старое движение не должно завершиться после возврата.
5. Пройти фразу в неправильном порядке: следующий знак не должен засчитаться.
6. Включить курсор ладонью, нажать щипком, прокрутить страницу, открыть / закрыть образец и вернуться кулаком. Проверить паузу двумя ладонями, образец двумя кулаками и повтор урока рукой.
7. Проверить Chrome/Edge на ноутбуке и Chrome/Safari на телефоне: консоль без ошибок, совпадение видео и скелета при resize/повороте телефона, нормальную работу после скрытия вкладки, близкую/далёкую кисть и плохое освещение.

После реальных испытаний пороги в `landmarks.js`, `gesture-rules.js` и `recognizer.js` можно адаптировать. Модель может ошибаться при перекрытии пальцев, плохом освещении, сильном наклоне или необычной моторике. Мимика и грамматика не анализируются.
